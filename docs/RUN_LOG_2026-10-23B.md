## The validator was checked against a bad skill, not just a good one

A passing validator proves nothing on its own, so the same commit was pointed at a throwaway directory
containing a skill whose `name` is `wrong` while the directory is `ghost-skill`, whose `description` is
empty, and which has no `metadata` block:

```text
FAIL .../ghost-skill/SKILL.md: name "wrong" does not match directory name "ghost-skill" (server derives skill:// URI from the directory)
FAIL .../ghost-skill/SKILL.md: frontmatter key "description" is missing or empty
FAIL .../ghost-skill/SKILL.md: frontmatter key "metadata" is missing or not a mapping

2 check(s) passed, 3 problem(s) found     # exit code 1
```

`npm run verify` check 18 does this automatically, in a temp directory it removes afterwards, which is why
the suite can be trusted to catch a regression in the validator itself.
