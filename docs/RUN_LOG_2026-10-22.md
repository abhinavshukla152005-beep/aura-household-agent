## Re-planning is reproducible, not weather-dependent

The rain-triggered re-plan needs a rainy observation, which depends on the machine it runs on, so the
curfew re-plan is the one a judge can force from any location. `POST /api/agent` with the body the
web device sends when **household clock = 23:05**:

```bash
curl -s localhost:8787/api/agent -H 'content-type: application/json' \
  -d '{"utterance":"set up a movie night for everyone","session":"living-room","hour":23}'
```

returned, in order:

```text
ok              household_profile   Load household rules, members and budget
ok              weather_now         Indoors or outdoors decides the plan
ok              media_search        Candidate titles
ok              pantry_status       Snacks already in stock
added-by-agent  media_search        Past the 22:00 screen-time curfew - offering audio instead of video
skipped         place_order         Every pick is already included - no spend authorisation needed
```

The same trace is what the "Why it decided that" panel paints. `hour` only changes the time the
planner reasons about; the weather, catalogue and pantry calls are live and unmodified.

## The web surface

Opened `http://localhost:8787` and clicked *set up a movie night for everyone*:

- both `ui://` MCP Apps templates render in their own sandboxed frames
  (`/api/resource?uri=ui://aura/cards`, `ui://aura/plan`), read back **through MCP** by the page's
  `Client` + `StreamableHTTPClientTransport`;
- the plan frame shows per-step latency and the `ADDED-BY-AGENT` / `SKIPPED` states;
- console output contained only the standard MCP Apps sandbox notice
  (`allow-scripts` + `allow-same-origin`) — no errors, no failed requests.

## What this log does not claim

- It is not a run on a real Alexa+ device or Fire TV hardware; the Alexa+ track's "build a simulated
  Alexa+ experience in a web app" allowance is what this is.
- The live run resolved weather to the machine's own location, so a judge in a dry city sees the
  curfew re-plan rather than the rain re-plan unless started with `AURA_OFFLINE=1` (bundled
  wet-evening fixture, rain risk 74%).
- Media titles come from the public iTunes Search catalogue when not offline, so third-party titles
  appear in a live run.
